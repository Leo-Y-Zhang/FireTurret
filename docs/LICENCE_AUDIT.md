# Third-party licence audit

Run **before** the Apache-2.0 relicence, not after, because a licence decision
constrains which dependencies are admissible — discovering an incompatible one
afterwards means either dropping a feature or breaking a promise already made.

Audited 2026-07-29 against the dependency set declared in `pyproject.toml`.

## ⚠ PySide6 is copyleft, and one of its options is outright incompatible

PySide6 is offered under a disjunction. **GPL-2.0-only is incompatible with
Apache-2.0** — the two cannot be combined in one distributed work, because
Apache-2.0's patent-termination clause is an additional restriction GPL-2.0 does
not permit. LGPL-3.0 *is* compatible, provided the linking is dynamic and the
user can relink.

So the licence taken here is **LGPL-3.0**, and the obligations that follow are:

- This project **does not bundle or redistribute PySide6**. It is an optional
  extra, installed by the user from PyPI, imported lazily, and absent from a core
  install. The core install has no copyleft dependency at all.
- This project's own code linking to it stays under its proprietary licence
  (see LICENSE; it was Apache-2.0 when this audit was first written). The LGPL's
  reciprocity applies to PySide6 itself, not to a work that merely uses its API.
- **Anyone who ships a bundled artefact** — a frozen executable, a container
  image, an appliance with Studio preinstalled — takes on LGPL-3.0
  obligations for the PySide6 portion: providing the licence text, and enabling
  the recipient to replace the library. That is a real obligation and it belongs
  to whoever does the bundling.

This is not a reason to drop Studio. It is a reason to state the boundary
rather than let somebody discover it after shipping.

## Model weights: none are shipped, and that is deliberate

The spec flags this specifically: **many YOLO-family weights are AGPL-3.0**, whose
copyleft obligations would conflict with this project's licensing if shipped, or
even if implied by an obvious default download.

Audited: **no model weights are checked into this repository.**
`vision/onnx_detector.py` takes a `--model PATH` argument and loads whatever the
operator supplies. There is no default download, no bundled `.onnx`, and no
implied weight set — so the licence of any weights is the operator's to satisfy,
and this project makes no claim about them.

If a default model is ever added, its licence must be audited **before** it is
referenced anywhere, and an AGPL-licensed one would force a choice between the
weights and the licence.

## Checked-in binary provenance

Every binary file in the repository is first-party, generated by this project's
own code from this project's own scenes:

| File | Provenance |
|---|---|
| `tests/golden/frames_default.npz` | Generated by `scripts/goldens.py frames` from the built-in synthetic renderer. No third-party imagery. |

**No photographs, no stock imagery, no third-party datasets, no scraped frames.**
The synthetic renderer is the reason that is true: every pixel the test suite
uses was drawn by code in this repository, so there is no image whose rights
someone else holds.

## Firmware

`firmware/turret_firmware/turret_firmware.ino` includes only `<Servo.h>` from the
Arduino core, which is LGPL-2.1. The same reasoning as PySide6 applies and is
weaker still: the sketch is source that a user compiles themselves against their
own Arduino installation, and nothing is redistributed.

## Sole authorship

Relicensing requires the right to relicense — which means every contributor must
either agree or have assigned rights. Verified by `git log`:

- **101 commits** at the time of the audit — the full private development
  history behind this repository, which was later published as a single
  commit — single author and committer throughout.
- Both identities are GitHub noreply addresses belonging to the same account.
- No third-party contributions, no vendored code, no copied snippets carrying
  another licence.

This doubles as the **anonymity gate**: the audit that proves the right to
relicense is the same audit that proves no real name has leaked into the history.
`scripts/verify.py` re-runs it, so a future commit under a personal email fails
the gate rather than being noticed later.
